## 説明を減らす再点検 — 2026-10-27

利用者の指摘に基づき、前節の「説明を増やして補う」構成を撤回した。画面上部の「評定データから、基本分析と結果の保存へ」はWeb由来ではなく配布版で追加した文言だった。現行Webソースの日本語タイトルは「MFRM｜評定データの分析」。内部の開発目的を利用者向けの見出しに移す必要はなかった。

**変更した判断基準：** その段階の操作、入力内容、実際に起きている問題を優先して表示する。一般的な説明を常設して理解を補ったことにはしない。

- 「データ → 設定 → 結果」の3画面に分けた。番号入りボタン、冒頭の宣伝的な見出し、常設の文字コード説明、得点範囲の注意、分析ID、通常時の一般的な妥当性注意を主画面から外した。形式・理論・分析情報・表の注記・図の読み方は必要時に開く。
- 入力はプレビューと「次へ」、設定は「列」「採点基準」と「分析」、結果は図表と保存を置く。「図で見る」は「図」に短縮した。図名は選択欄で分かるため画面内ではタイトルを重複させず、保存画像にはタイトルを付ける。
- 対象者・得点の列を要因の候補から除き、同じ列の重複指定を選択肢で防ぐ。採点基準と観測得点を別に示す。整数の入力漏れは該当欄にフォーカスし、設定画面に具体的な修正内容を表示する。既存の未保存結果を捨てる確認は入力が妥当と分かった後に行う。
- データ・設定への移動だけでは結果を捨てない。設定が分析時から変わった場合のみ「前回の分析」を表示する。推論の保留や保存時からの資格変更は結果画面に残し、説明の削減を重要な制約の非表示にはしない。

[参照Shinyアプリ](https://langtest.jp/shiny/mfrm/)の短い機能名、入力と結果の分離、適合度指標の選択を参考にした。ただし、取得できたのはページの構成・文言であり、ブラウザー操作環境が利用できず実操作の比較は行っていない。タブ数の全面移植や赤青の合否表示は採用しない。

**Infitの再点検：** MnSqとZSTDを区別する。Infit MnSqは非負で、モデルの基準は1。−2〜2をMnSqの許容範囲にはできない。近似ZSTDの±2は標準正規近似に基づく参照で、評定数・自由度・多重性・近似の成立条件に左右される。[Winstepsの診断説明](https://www.winsteps.com/winman/misfitdiagnosis.htm)も平均平方と標準化統計を区別し、平均平方を先に検討するよう説明している。[Schulzの論考](https://www.rasch.org/rmt/rmt34d.htm)は標準化適合度の標本サイズ依存と元の反応内容の点検を扱う。0.5〜1.5等の経験則も一律の合格保証にはしない。

Web開発版と配布版のPathwayをInfit MnSqの初期表示に統一し、1の参照線のみ示す。ZSTDを選んだときだけ0と±2の線を描き、合格域の塗り分けや自動分類は行わない。MnSq軸は0と少なくとも2を含め、近接する値の差だけを拡大しない。同一指標・要因でWeb／nativeの座標と軸範囲を共有する。図とHTMLの保存にも選択中の指標・要因を引き継ぐ。エンジンのMnSq／ZSTD計算は変更しない。

今回の証拠は`validation/generated/desktop_steps_20261027/`。関連107項目、保存設定の追従を含む最終47項目、最後の軸範囲変更に影響する4項目が各工程で通過した（重複あり）。Tk実部品で画面遷移・入力不備・中止／再実行・再読込・図の切替／hover・各形式の保存・前回結果の表示・保留表示を確認した。ファイル選択先は検証用に供給している。実利用者の理解や操作の改善効果、公開Webの反映・再受入、Windowsの確認は未完了。

この変更を含むmacOS arm64パッケージをビルドし、内蔵ランタイムの中止→失敗→再実行、見本CSV、3図入りHTML、PNG、別プロセス復元を確認した。保存時と復元後のHTMLは全バイト一致。ビルド元hashとコピー先アドホック署名を照合した。GUIの実部品確認と凍結ランタイムの処理確認は別の証拠であり、クリーン端末や一般配布の受入へ広げない。

- `mfrm_app/engine.py`へ基本分析の依存関数群を移動し、Webも同じ関数をimportする。数値関数を二重実装しない。
- 移動した147関数／クラスの本体はASTで移動前と一致。別の1クラスはPCA理由の意味情報だけを保持するよう変更し、翻訳はWeb表示側に残した。定数を含む移動は169定義。
- `run_basic_analysis()`は列・得点範囲の確認、推定、診断、表の生成、出典の保持を一続きにする。Streamlit本体やsession_stateを読み込まない。
- 公開用の推定値表は`reporting_facts.publication_measure_table()`を共用する。保留中のSE・区間を空欄にする規則や、条件付き近似の説明を配布版だけで緩めない。
- 初期画面はPCA・厳密周辺診断・バイアス再推定を実施しない。この範囲をプロジェクトと報告に記録する。

Webの全画面を分割したわけではなく、全モデルのデスクトップ対応も意味しない。

## プロジェクト形式の契約

schema 1はRSM／JMLEの基本分析用で、原入力、前処理済み入力、列対応・得点範囲、結果、診断、表、分析ID、計算版・ソース識別、保存時の利用条件を保持する。
プロジェクトには入力データと識別子を含む。入力を除いた閲覧専用形式は未対応。

型付きJSONで、文字列と数値のID、欠測マーカー、カテゴリーの水準・順序、配列のdtype・shapeを区別する。
Python pickleや動的なクラス読込を交換形式に用いない。内容のfingerprintと分析IDを照合し、不一致、未知の版、不完全な列対応、対応外の型を拒否する。
fingerprintは内容の整合確認であり、作成者を認証する電子署名ではない。

読み込み時は保存時の資格を保持し、表示・報告では現在の資格を再適用する。判定が変わればその旨を表示する。
最適化の失敗・不明を成功へ変えない。結果の保存と途中の最適化からの再開を区別し、後者は未対応。
`hess_inv`という最適化内部オブジェクトは保存しない。報告済みの不確実性の値・条件・理由は保持する。

保存は一時ファイルを書き終えてから置き換える。保存失敗時は元ファイルを保持する。
初期形式の読込・保存上限は128 MiB。全研究オブジェクト、全キャッシュ、全pandas型を保存する汎用形式ではない。

## 起動とビルド

開発環境からの起動：

```sh
python3 desktop_app.py
```

対象OS上の専用環境へ`requirements-desktop-build.txt`を導入し、次を実行する。
macOSの今回の実証はPython 3.14、Tcl/Tk 8.6.17、arm64。最低対応macOS版はまだ認定していない。

```sh
python3 scripts/build_desktop.py --output /path/to/local-build
```

Windowsでは対応するPythonコマンドとWindowsの出力パスを使う。
ビルド先にソースhash・依存版のmanifest、PyInstaller作業領域、`dist`ができる。
macOSでは`MFRM-Desktop.app`、Windowsでは`MFRM-Desktop`ディレクトリ内の実行ファイルを対象に確認する。
macOSの試作はPyInstallerによるアドホック署名であり、Developer ID署名・公証は実施していない。

開発用の配布物チェックは次の2段階。`--check-project`は推定・診断関数を呼べば失敗する設定で復元する。

```sh
MFRM-Desktop --smoke-test /path/to/check-output
MFRM-Desktop --check-project /path/to/check-output/作文.mfrm --output-dir /path/to/reopened
```

macOSは`.app/Contents/MacOS/MFRM-Desktop`、Windowsは`.exe`を指定する。
これは実GUIのファイル選択、実利用者の理解、Python未導入端末の受入を代替しない。

パッケージにはPythonランタイム、Tk、数値ライブラリ、MatplotlibのTk/SVG用モジュール、必要な翻訳資源を含める。
ビルド元macOSによる互換性の制約と、凍結アプリの`freeze_support()`が必要な点は
