# 求積の比較を読み、手元で再確認する

## 水準・指定した差の近似区間を得る

結果の計算確認にある「構造効果と指定した差の近似区間」を開き、ファセットを選びます。
研究計画で定めた差が必要なら、比較する水準Aと基準Bを選び、「近似区間を計算」を押します。
通常の操作で新しく計算する区間は点ごとの95％区間です。数値基準を満たす対象にはSE・区間を表示し、
満たさない場合は理由と推定値を残してSE・区間を空欄にします。再推定や中心化設定の変更は行いません。

これは固定した正規母集団SDと応答モデルに条件づけた漸近近似です。受験者間の独立性、
割当・欠測の無視可能性、識別された内点と情報量の増大等を仮定します。
`CIEligible=True` はこの区間の数値的利用可否、`CoverageQualified=False` は
有限標本での被覆率を認定していないことを意味します。個人得点、自由SD、同等性検定、多重比較、
モデル選択などの保留は別です。一般表の保留を一括で解除するものではありません。

表・図・CSV・HTMLは同じ区間記録を使います。通常のWord／PDF／HTMLレポートにも
「Specified Structural Intervals」表として追加されます。JSONを保存しておけば、
同じ分析・数値ソース・実行環境で再推定せずに読み込めます。入力・返却点・対象・数値記録の
改変や別分析への流用は拒否します。JSON単体は元データを含む完全な分析プロジェクトではありません。

区間の判定では分析時q点と同一点の2q−1点を比較し、SE尺度の停止誤差と全共分散の変化を確認します。
個別水準のSEが同じでも差のSEは変わり得るため、共分散を含めて判定します。
これは求積感度の確認であり、連続積分に対する厳密な誤差上界ではありません。
以下の追加のGH比較は技術的な確認記録であり、それ単独で区間の利用資格を与えません。

## 同じ推定値で追加の求積比較を行う

画面の「積分点を変えて確認」で、EAP差・事後SD差・構造効果のSE差を分けて確認します。
**この操作は、元の推定値と母集団SDを固定した比較です。再推定はしていません。**

## 何を確認したいですか？

| 確かめたいこと | 必要な比較 |
|---|---|
| 今の積分点で、推定計算を十分に進めたか | 終了理由と勾配を確認し、必要なら同じ積分点で追加の最適化を行って推定値の変化を調べます |
| 今の推定値で、積分点を変えると得点が変わるか | 画面の同一点比較。EAPと事後SDを別々に確認します |
| 積分点を変えて分析し直しても、結論が変わらないか | データ・モデル・母集団SDをそろえて再推定し、推定値と得点を比較します |
| 積分の近似がどの程度正確か | 同じ推定値で、精度を点検した連続積分などの参照計算と照合します |

基準の行の差が0なのは、同じ計算との比較だからです。精度の証明ではありません。
EAPは個人得点の事後平均、事後SDは校正値を固定したときの得点の不確実性です。
母集団SDや構造パラメータの標準誤差とは異なります。各列の最大差は、別の人に生じることもあります。
NLL差は全受験者の負の対数尤度の合計の差です。異なる求積でNLLが低くなっただけでは、
より正確な推定になったとは判断できません。

## 構造効果のSEと停止誤差

ファセットの水準と中心化した段階効果について、SEも比較します。母集団SDを固定した周辺尤度の
全観測情報行列を使い、ファセット間・段階効果との共分散を含めます。情報行列を `H`、自由座標から
表示する効果への変換を `J` とすると、SEは `sqrt(diag(J H⁻¹ Jᵀ))` です。
制約から決まる最後の水準・段階も含みます。ここでのSEは技術的な計算値であり、
この確認によって論文での推論に利用可能となるわけではありません。

「SE相対変化の最大値」は比率で、0.01なら1％です。「局所補正量／SEの最大値」は
`max |J H⁻¹g| / SE` で、`g` は合計NLLの勾配です。Newton更新では返却座標から `H⁻¹g` を引きます。
局所的な近似であり、再推定で実測した変化ではありません。一律の合格基準も設定していません。
二つの最大値は別の効果に生じる場合があります。基準行のSE差は0ですが、停止誤差の近似は0とは限りません。

固有値の底上げやridge補正は行いません。情報行列が正定値でない、または設計の階数が不足する場合は、
SE比較を空欄にし、JSONに理由を残します。尤度が改善し続ける構造効果の方向を証明できた場合も表示します。
その方向が検出されなかったことは、有限な最尤推定値の存在証明ではありません。
JSONには情報行列・共分散行列・対象への変換・診断値を保存します。
正定値であることだけでは、数値精度や区間の被覆率は確定しません。

画面の対応は、単位重みの固定SD RSM／PCM、単純な中心化です。既定の全構造ファセット中心化と、
1つの構造ファセットを非中心化する設定に対応します。
アンカー・群別制約・ダミー・回帰・正則化は対象外です。分析時のGH点数3〜121とGH31／61／121を比較し、
SD 0.05〜10、最大64自由座標に制限します。評定数だけでは制限せず、集約計算配列がメモリ上限を超える場合は未計算とします。
後述するローカル再推定コマンドは、**これより狭いPCM専用の対応範囲**です。
画面で確認できる入力を全て処理できるわけではありません。

勾配が小さいことは、選んだ積分点での計算についての情報です。連続した母集団分布を
十分正確に近似できているとは限りません。また、EAP差がほぼ0でも事後SDに差が残る場合があります。
再推定後の得点の変化には、積分の違いに加え、校正値が動いた影響も含まれます。

結論に影響しそうな差があれば、元の結果を保存してから追加の比較へ進みます。
差が小さい場合も、一律に「問題なし」とは判定できません。必要な精度は研究目的に合わせて、
比較結果を見る前に定めます。次数だけを増やして確認を終えないようにします。

## 外部ソフトとの一致と、積分の精度

RとPythonなどで結果が違う場合は、言語だけを理由にせず、データ・モデル・制約・校正値・
母集団SD・積分点・重み・得点法をそろえて比較します。同じ条件で一致することは、
同じ計算を再現できた根拠です。その近似が十分正確かは、別に確認する必要があります。
同じ推定値での比較と、各ソフトで再推定した後の比較も区別してください。

## 保存するもの

1. 画面の「確認結果を保存（JSON）」で同一点比較を保存します。
2. 「レポートと出力 → 確認事項 → 詳しく確認する資料 → 外部ソフトと比較する」から、比較用ZIPを保存します。
3. ZIPを展開し、`data.csv` と `analysis_snapshot.json` を同じフォルダーのまま保管します。
   データ・識別ラベル・設定を編集せず、元の分析と一緒に非公開で保存します。

JSONだけでは、下記の再確認を実行できません。ZIP内の `comparison_report.html` は、
外部比較を記録するための未評価のひな形です。ダウンロードしただけで比較済みにはなりません。

## Pythonで再推定と連続積分を確認する（開発用）

この手順には、`validation/mml_fixed_sd_accuracy_check.py` を含むアプリのソース一式と、
そのソースで指定されたPython依存パッケージが必要です。比較用ZIPにPythonの確認エンジンは含まれません。
元の分析に対応したソース・実行環境を用意し、版と記録したソースハッシュを残してください。

対応範囲は、固定平均0・固定母集団SDのMML PCM、3つの各2水準ファセット、得点0〜3、
単位重み、アンカー・回帰・罰則なしです。ステップファセットのみ非中心化し、他のファセットは中心化します。
各ファセットの組合せで全4カテゴリの観測が必要です。個人・セルの欠測は保持しますが、
同じ個人・セルの重複回答は対応外です。分析時のGH次数は31・61・121、SDは0.05〜10、
回答行は1,000以下に制限しています。これは入力の対応範囲であり、全条件での精度保証ではありません。
対応外の場合、設定やデータを変えて無理に実行せず、そのモデルに合う検証を別途行います。

以下のパスを実際の場所へ置き換え、Terminalで実行します。出力先には**まだ存在しないフォルダー**を指定します。

```sh
cd "/path/to/MFRM_Python_Application"
python3 validation/mml_fixed_sd_accuracy_check.py \
  --input "/path/to/extracted/MFRM_Cross_Engine_Validation_Bundle" \
  --output "/path/to/new/pcm_check_01"
```

GH31・61・121のそれぞれを、元の推定値とゼロの2開始点から再推定します。
連続積分では元の点と再推定点を評価し、連続積分を目的関数とする再最適化はしません。
元のファイルを上書きせず、全経路・失敗・入力・ソース・実行環境を出力先へ保存します。
解析担当者は実行前に `protocol.json` に記録される設定をソースで確認してください。
既定の数値目安は開発用で、研究上の同等性の幅ではありません。

## 結果の読み方

- `summary.json`：予定した6経路がすべて評価されたか、最終勾配、開始点間の差を確認します。
  最適化が終了しても、積分精度や標準誤差・信頼区間が確認されたことにはなりません。
- `q*_same_point.json`：元の推定値での各次数の計算です。
- `q*_original.json` と `q*_zero.json`：各開始点からの再推定結果です。
  `decomposition` は「同じ再推定点での積分差」と「連続積分上での再推定による変化」を分けます。
  総変化の基準は、**元の推定値を連続積分で評価した値**です。元の画面の有限GH値とは異なります。
  符号付きの個人別差は足し合わされますが、最大絶対差同士を足してはいけません。
- `reference_checks_pass` がfalseなら、設定間差と `allowances` を調べます。
  この開発用スクリプトは、全員分を集約した保守的な誤差見積もりを使います。
  未達は真の積分誤差の大きさを実測した意味ではありません。個人別評価などで理由を調べ、
  旧記録を残します。別の開発例で良い結果が得られたことを、今回の合格理由には使えません。

TAM／ConQuestとの比較はZIP内の `README_cross_engine.md` を参照してください。
その固定格子やConQuestの得点計算は、上記のGH比較とは計算条件が異なります。
外部結果や再推定候補を、この画面の正式な分析結果へ読み込む機能はありません。
