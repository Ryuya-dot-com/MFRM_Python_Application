# MFRM Streamlit — v0.2.0-beta Plan

Checklist tracking the four-phase UX / feature expansion from the
v0.1.2-beta baseline. All work lands on `main` as atomic commits;
the final `v0.2.0-beta` git tag is applied after every phase ships.

**Philosophy (decided up-front):**

- Bayesian / advanced-model execution stays **local** — the app only
  generates Stan code + a runner script that users run on their own
  machine. Streamlit Cloud itself never compiles or samples.
- Keep `streamlit_app.py` as a **single file** (monolith).
- Ordering: **A → B → D → C**.
- Release style: cut `v0.2.0-beta` tag once all four phases merge.
- Tests: inline `_self_test_*` functions in the same style as the
  existing self-tests.
- Docs: update `README.md`, `CHANGELOG.md`, and `docs/` alongside code.
- Merge cadence: full-auto, commit → push per feature, no interactive
  approvals between items.

## Working rules reminder

1. `git pull origin main` at the start of every work session —
   GitHub is the source of truth, not any local Dropbox copy.
2. Commit and push per feature (never batch unrelated work).
3. Never skip pre-commit hooks.
4. Any silent-fail / empty-return introduced in new code must carry
   a `_skip_reason` (or equivalent) so the UI can explain it.
5. Every new user-facing pipeline step gets a `run_status.write(...)`
   so the `st.status` accordion reflects what the app is doing.
